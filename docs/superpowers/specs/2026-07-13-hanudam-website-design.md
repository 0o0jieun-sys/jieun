## 1. 목적

하누담의 투플 한우 전문성과 완전 개별룸의 고급스러운 경험을 보여주고, 방문자를 예약 또는 단체 문의로 전환하는 매장 홈페이지를 만든다. 검색엔진과 생성형 AI가 매장 정보를 정확히 이해하도록 SEO, 로컬 SEO, AEO, GEO를 함께 설계한다. 관리자는 코드를 수정하지 않고 메뉴, 가격, 사진, 영업정보, 공지, FAQ, 팝업과 승인된 고객 리뷰를 관리할 수 있어야 한다.

## 2. 확정된 핵심 결정

- 시각 방향은 Pencil의 `FINAL · A+C 하이브리드`를 기준으로 한다.
- A안의 시네마틱하고 고급스러운 히어로와 C안의 명확한 예약 분기를 결합한다.
- 2~29명은 네이버 예약으로 연결한다.
- 30명 이상은 홈페이지 단체 문의 또는 전화 문의로 연결한다.
- 한우 온라인 주문은 외부 쇼핑몰이 생기기 전까지 전화 문의로 제공한다.
- 초기 사진은 매장이 권리를 보유한 네이버 플레이스 공식 사진만 사용하고, 고객 리뷰 사진은 사용하지 않는다.
- 추후 제공되는 원본 사진은 같은 콘텐츠 필드에서 교체할 수 있어야 한다.
- 고객용 본문, 가격, 버튼, 입력값, 라벨, 오류 메시지는 16px 미만으로 내리지 않는다.
- 고객 리뷰는 자동 수집하지 않고, 사용 동의가 확인된 항목만 관리자가 선별 등록한다.

## 3. 목표와 비목표

### 목표

- 첫 화면에서 투플 한우, 완전 개별룸, 예약 방법을 즉시 이해시킨다.
- 가족 모임·기념일과 기업 회식·단체 모임 고객을 같은 비중으로 설득한다.
- 모바일에서 네이버 예약과 전화 문의를 항상 쉽게 찾을 수 있게 한다.
- 상호명, 주소, 전화번호, 영업시간, 메뉴와 가격의 일관성을 유지한다.
- 관리자 수정이 공개 화면과 검색용 데이터에 안전하게 반영되게 한다.
- 배포 전후 SEO·GEO 품질 저하를 검사할 수 있게 한다.

### 비목표

- 자체 예약 달력, 좌석 재고 또는 결제 기능은 만들지 않는다.
- 자체 쇼핑몰은 만들지 않는다.
- 네이버 방문자 리뷰를 HAR 또는 비공개 GraphQL로 자동 수집하지 않는다.
- 고객 관계 관리, 문의 티켓 관리 또는 복잡한 관리자 권한 체계는 만들지 않는다.
- 확인되지 않은 수상, 인증, 최상급 표현 또는 조작된 후기를 사용하지 않는다.

## 5. 시각 및 접근성 원칙

- 기본 인상은 세련되고 모던한 고급 고깃집이다.
- 딥 와인, 블랙, 따뜻한 아이보리를 중심으로 사용하고 금색은 1++ 등급과 정제된 강조에만 제한한다.
- 큰 사진, 충분한 여백, 짧고 구체적인 문장을 사용한다.
- 과한 전통 문양, 금박 질감, 장식용 그래픽, 자동 재생 영상과 강한 애니메이션은 사용하지 않는다.
- 공개 화면 본문은 기본 17px/1.7, 보조 정보는 최소 16px/1.6을 기준으로 한다.
- 주요 버튼은 최소 높이 52px와 명확한 포커스 상태를 갖는다.
- 일반 텍스트 대비는 WCAG AA 4.5:1 이상을 목표로 한다.
- 키보드만으로 모든 링크, 버튼, 폼과 메뉴를 사용할 수 있어야 한다.
- `prefers-reduced-motion`을 존중하고 핵심 정보는 움직임 없이도 이해할 수 있어야 한다.

전문 콘텐츠는 다음 주제를 중심으로 확장한다.

- 투플 한우의 의미와 하누담의 선별 기준

2026-07-13 HAR 분석에서 네이버 플레이스 `1745436509`의 방문자 리뷰 응답 구조와 당시 총 335건을 확인했다. 이 숫자는 시점에 따라 변하므로 자동 동기화하거나 영구적인 사실처럼 고정하지 않는다.

- 마스킹한 닉네임
- 짧은 인용문

- 네이버 원문 URL

사용 동의가 확인되지 않은 문서는 발행할 수 없다. 공개 리뷰에는 `네이버에서 리뷰 보기` 링크를 제공한다. 리뷰 원문이 삭제되거나 권리자가 철회를 요청하면 관리자가 즉시 숨길 수 있어야 한다.

## 8. SEO·로컬 SEO·AEO·GEO

- 모든 중요한 본문은 초기 HTML에서 읽을 수 있게 렌더링한다.
- 페이지마다 고유한 title, description, canonical URL, Open Graph 정보를 제공한다.
- sitemap.xml, robots.txt, 의미 있는 URL, 내부 링크와 Breadcrumb를 제공한다.
- 이미지에는 사실적인 대체문구, 크기 정보와 적절한 포맷을 적용한다.
- `Restaurant` 또는 적합한 `LocalBusiness`, 메뉴, Breadcrumb 구조화 데이터를 사용한다.
- FAQ는 질문 직후 짧은 답을 먼저 제공하고 필요하면 세부 설명을 이어간다.
- 구조화 데이터와 FAQ는 기계 이해를 돕는 용도이며 검색 노출을 보장한다고 표현하지 않는다.
- 상호명, 주소, 전화번호, 영업시간은 홈페이지, 네이버 플레이스, 카카오맵과 구글 비즈니스 프로필에서 동일하게 유지한다.
- `llms.txt`는 보조 발견 파일로만 사용하며 표준 SEO를 대체하지 않는다.
- 배포 전후에 GEO Optimizer와 Codex SEO 방식으로 크롤링, 메타데이터, 구조화 데이터, 로컬 정보 일관성, 성능, 인용 가능성과 드리프트를 검사한다.

권위 있는 매장 정보는 네이버 플레이스를 우선 대조 대상으로 삼고, 웹사이트 관리 값이 다를 때는 발행 전에 관리자가 불일치를 확인하게 한다. 정보가 확인되지 않으면 추측해서 채우지 않는다.

## 9. 기술 구조

### 구성 요소

- Next.js 16: 고객용 페이지, 메타데이터, 구조화 데이터, 단체 문의 처리
- Sanity Studio: 콘텐츠 초안, 미리보기, 발행과 버전 이력
- Vercel: 프로덕션 배포, 서버 함수와 콘텐츠 갱신
- Resend: 30명 이상 단체 문의를 `GROUP_INQUIRY_TO_EMAIL` 환경변수에 지정한 운영 이메일로 전달
- 네이버 플레이스: 2~29명 예약과 리뷰 원문

현재 프로젝트의 Next.js 16.2.10, React 19.2.4, Tailwind CSS 4, shadcn Button/Card 구성을 유지한다. 구현 전 `node_modules/next/dist/docs/`의 현재 버전 문서를 확인한다.

### 콘텐츠 경계

Sanity는 공개 콘텐츠만 저장한다.

- siteSettings: 상호, 연락처, 주소, 영업시간, 주차, 예약 URL, 주문 문의
- homePage: 히어로, 소개, 섹션 순서와 CTA
- menuItem: 부위, 설명, 가격, 중량·제공 기준, 원산지, 이미지, 공개 상태
- room: 이름, 인원, 시설, 설명, 이미지, 공개 상태
- notice: 제목, 본문, 공개 기간, 팝업 여부
- faq: 질문, 답변, 카테고리, 정렬
- testimonial: 승인된 고객 리뷰 필드
- seoFields: 페이지별 제목, 설명, 공유 이미지와 색인 여부

단체 문의의 이름, 연락처와 요청사항은 Sanity에 저장하지 않는다.

### 발행 흐름

`관리자 수정 → Sanity 초안 저장 → 미리보기 → 발행 → 서명된 갱신 요청 → Next.js 캐시 갱신 → 공개 본문과 검색 데이터 갱신`

발행 실패 시 관리자에게 공개되지 않았음을 명확히 알리고 이전 공개 버전을 유지한다. Sanity가 일시 중단되어도 마지막 공개 콘텐츠를 제공한다.

## 10. 단체 문의 흐름

필수 입력은 이름, 연락처, 희망일, 예상 인원, 요청사항과 개인정보 처리 동의다. 서버에서 다시 검증하고, 숨은 필드와 요청 횟수 제한으로 기본 스팸을 차단한다.

`폼 작성 → 클라이언트 검증 → 서버 검증 → 메일 전송 → 성공 확인`

전송 실패 시 입력 내용을 유지하고 재시도 및 전화 문의를 안내한다. 전송 버튼은 처리 중 비활성화하여 중복 제출을 막는다. 분석 도구에는 문의 필드 값을 보내지 않고 성공 또는 실패 이벤트만 보낸다.

## 11. 오류와 대체 동선

- 네이버 예약 URL 오류: 전화 문의를 대체 행동으로 제공한다.
- 단체 문의 전송 실패: 입력 유지, 재시도, 전화 문의를 제공한다.
- CMS 또는 갱신 실패: 마지막 공개 콘텐츠를 유지한다.
- 이미지 실패: 크기가 고정된 대체 이미지를 표시해 레이아웃 이동을 막는다.
- 지도 로딩 실패: 텍스트 주소, 복사, 길찾기 링크를 유지한다.
- 콘텐츠가 비어 있음: 해당 섹션을 숨기고 빈 카드나 깨진 제목을 노출하지 않는다.

오류 문구는 원인 코드보다 고객이 다음에 할 행동을 먼저 설명한다.

## 14. 배포 승인 기준

- 핵심 페이지가 프로덕션에서 HTTP 200으로 응답한다.
- 2~29명 네이버 예약, 전화, 길찾기와 30명 이상 문의 동선이 실제로 작동한다.
- 문의 성공·실패·중복 제출이 예상한 상태를 보여준다.
- 고객용 본문과 폼 텍스트가 16px 이상이다.
- 모바일에서 가로 스크롤, 겹침, 잘림과 빈 주요 섹션이 없다.
- title, description, canonical, sitemap, robots.txt와 구조화 데이터가 유효하다.
- 매장 정보가 권위 있는 외부 프로필과 일치한다.
- HAR, 캡차 토큰, 인증 정보와 문의 개인정보가 소스 또는 공개 배포물에 없다.
- 프로덕션 배포는 항상 `vercel --prod --yes`를 사용한다.
