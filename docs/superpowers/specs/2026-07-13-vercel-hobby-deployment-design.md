# Vercel Hobby 연습 사이트 배포 설계

- 작성일: 2026-07-13
- 대상 프로젝트: `C:\vibecoding\my-shop`
- 용도: 개인 연습 및 테스트 전용

## 목표

현재 Next.js 16 프로젝트를 GitHub 비공개 저장소에 보관하고 Vercel Hobby 계정과 연결한다. 최초 배포 후에는 기본 브랜치에 변경 사항을 올릴 때마다 Vercel이 자동으로 빌드하고 `*.vercel.app` 주소에 배포하도록 한다.

## 범위

- GitHub 사용자 `0o0jieun-sys` 소유의 비공개 `my-shop` 저장소를 사용한다.
- Vercel Hobby 계정의 개인 프로젝트로 연결한다.
- 최초에는 Vercel이 제공하는 무료 `*.vercel.app` 주소만 사용한다.
- 별도 도메인 구매, 상업용 공개, 결제 기능, 운영 데이터베이스 구성은 이번 범위에서 제외한다.
- 이 배포는 Vercel Hobby 정책에 맞는 개인·비상업 연습 용도로만 유지한다.

## 선택한 방식

GitHub와 Vercel의 Git 연동을 사용한다. CLI로만 직접 배포하는 방법보다 초기 연결 단계는 조금 더 길지만, 이후 코드 변경 시 자동 배포되고 변경 이력과 복구 지점이 남으므로 초보자가 반복 연습하기에 적합하다.

## 구조와 데이터 흐름

1. 로컬 `my-shop` 프로젝트에서 검사 명령을 실행한다.
2. 프로젝트를 Git 저장소로 초기화하고 필요한 소스만 커밋한다.
3. GitHub의 비공개 `my-shop` 저장소에 기본 브랜치를 업로드한다.
4. 현재 로컬에 남아 있는 Vercel 프로젝트 연결이 사용자 계정의 프로젝트인지 확인한다.
5. 연결이 맞으면 기존 Vercel 프로젝트에 GitHub 저장소를 연결하고, 다르면 새 개인 프로젝트로 가져온다.
6. Vercel이 의존성을 설치하고 `npm run build`를 실행한다.
7. 빌드 성공 결과를 `*.vercel.app` 주소에 게시한다.
8. 이후 기본 브랜치에 푸시하면 프로덕션 배포가 자동 갱신된다.

## 보안과 저장소 정책

- GitHub 저장소는 비공개로 생성한다.
- `.env*`, `.vercel`, `node_modules`, `.next`, 로그와 인증 키는 GitHub에 올리지 않는다.
- 비밀번호, GitHub 인증 코드, Vercel 인증 코드, 액세스 토큰은 대화나 저장소에 기록하지 않는다.
- 나중에 환경변수가 필요하면 Vercel 프로젝트 설정에서 별도로 등록한다.

## 오류 처리와 복구

- 로컬 `npm run lint` 또는 `npm run build`가 실패하면 GitHub 업로드 전에 원인을 해결한다.
- Vercel 빌드가 실패하면 Vercel의 Build Logs에서 최초 오류를 확인한다.
- 새 배포에 문제가 있으면 Vercel의 이전 성공 배포를 다시 활성화하거나 Git에서 문제 커밋을 되돌린다.
- 무료 사용량 한도에 도달하면 배포가 일시 중지될 수 있으므로 Vercel Usage 화면에서 사용량을 확인한다.

## 검증 기준

- 로컬에서 `npm run lint`와 `npm run build`가 성공한다.
- GitHub에서 `my-shop` 저장소가 비공개로 표시된다.
- Vercel 배포 상태가 Ready로 표시된다.
- 발급된 `*.vercel.app` 주소가 HTTP 200으로 열리고 현재 홈페이지가 보인다.
- 소스에 작은 변경을 커밋한 뒤 자동 재배포가 동작한다.

## 이후 확장

연습 사이트가 완성되어 실제 식당 영업에 사용하려면 Vercel의 상업용 요금제로 변경하거나 상업 이용이 가능한 다른 호스팅을 선택한 뒤 별도 도메인을 연결한다.
